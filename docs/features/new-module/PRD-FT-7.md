Como ficaria no PRD usando “Users should be able to”
Feature 6 — Funil de Recrutamento
Objetivo

Permitir que o RH acompanhe processos seletivos por vaga, mova candidatos entre etapas, registre desistências/reprovações, colete feedbacks internos e visualize métricas do funil de contratação.

User stories principais

Users should be able to criar vagas de emprego.

Users should be able to cadastrar candidatos.

Users should be able to vincular candidatos a uma vaga.

Users should be able to visualizar candidatos em um funil por etapa.

Users should be able to mover candidatos entre etapas do funil.

Users should be able to registrar motivo de desistência do candidato.

Users should be able to registrar motivo de reprovação do candidato.

Users should be able to registrar feedback interno sobre o candidato.

Users should be able to preencher scorecard simples de entrevista.

Users should be able to visualizar histórico do candidato no processo seletivo.

Users should be able to acompanhar métricas do funil por vaga.

Users should be able to identificar em qual etapa os candidatos mais desistem.

Users should be able to identificar em qual etapa os candidatos mais são reprovados.

Users should be able to visualizar tempo médio dos candidatos em cada etapa.

Users should be able to converter candidato contratado em colaborador.

Métricas que realmente importam

Eu não encheria de gráfico no começo.

Foque nessas:

1. Conversão por etapa

Exemplo:

100 cadastrados
60 passaram para triagem
30 foram para entrevista RH
15 foram para entrevista gestor
5 receberam proposta
2 foram contratados
2. Abandono por etapa

Exemplo:

40% dos candidatos desistem após teste técnico

Isso indica que o teste pode estar longo, mal explicado ou desalinhado.

3. Reprovação por etapa

Exemplo:

70% reprovam na triagem

Isso pode indicar problema na fonte de candidatos ou descrição da vaga.

4. Tempo médio por etapa

Exemplo:

Candidatos ficam 8 dias parados em Entrevista Gestor

Isso mostra gargalo operacional.

5. Origem dos contratados

Exemplo:

LinkedIn trouxe 80 candidatos e 1 contratação.
Indicação trouxe 10 candidatos e 3 contratações.

Isso mostra qualidade do canal.

Minha recomendação de escopo final

Eu diria para você implementar, mas como:

Módulo simples de Recrutamento e Funil de Candidatos

Não chame de ATS completo no começo.

Chame de algo mais simples:

Funil de Recrutamento
Pipeline de Candidatos
Gestão de Processos Seletivos
Recrutamento Simples
Vagas e Candidatos

Promessa:

“Acompanhe candidatos por etapa, entenda onde eles desistem e transforme contratações em colaboradores dentro da plataforma.”

Isso encaixa perfeitamente no seu SaaS.

Veredito

Sim, é válido.

Mas eu faria com esta regra:

O módulo de recrutamento deve terminar onde começa a vida do colaborador.

Ou seja:

Candidato contratado → vira colaborador → entra no ciclo de gestão de pessoas

Essa é a conexão estratégica.

A feature vale muito porque amplia o produto de:

“gestão de colaboradores”

para:

“gestão da jornada de pessoas na empresa.”
